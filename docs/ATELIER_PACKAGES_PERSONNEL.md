# معماری آیتم، پکیج، دسترسی پرسنل و هزینه مراجعه

## آیتم و پکیج قرارداد

جدول موجود `studio_catalog` منبع تنظیمات آیتم‌ها (`service`) و پکیج‌ها (`package`) است. شناسه آیتم‌های هر پکیج در `specifications.itemIds` نگهداری می‌شود و فقط به آیتم فعال اشاره می‌کند. انتخاب پکیج در فرم قرارداد، آیتم‌های آن را به رکوردهای عادی `studio_contract_items` تبدیل می‌کند؛ بنابراین قیمت، تعداد و عنوان قرارداد snapshot هستند و تغییر بعدی کاتالوگ اثری بر قرارداد تاریخی ندارد. آیتم سفارشی نیز بدون وابستگی به کاتالوگ پشتیبانی می‌شود.

## حقوق ثابت و دستمزد کار

`studio_personnel.fixed_salary` و `payment_cycle` فقط تنظیم حقوق ثابت پرسنل هستند. برای پروفایل‌های متصل، مبلغ حقوق ثابت با `employees.base_salary` همگام می‌شود. این تنظیم به‌تنهایی هزینه یا پرداخت ماهانه تولید نمی‌کند؛ ایجاد بدهی/هزینه حقوق نیازمند عملیات صریح مالی است.

دستمزد پیش‌فرض بر اساس نوع فعالیت دیگر در جریان‌های جدید خوانده یا نوشته نمی‌شود و API/UI آن حذف شده است. جدول قدیمی `studio_personnel_default_wages` فقط برای حفظ تاریخچه نگه داشته شده و migration مخرب ندارد. دستمزد برنامه‌ریزی قرارداد و مراجعه روزانه همیشه مبلغ صریح همان تخصیص و یک snapshot مستقل است.

## حساب و دسترسی پرسنل

حساب ورود پرسنل از معماری موجود `employees`، `employee_accounts`، `roles` و hash امن رمز عبور استفاده می‌کند. جدول افزوده `employee_permissions` دسترسی مستقیم هر کاربر را نگه می‌دارد. نقش `atelier_personnel` دسترسی پیش‌فرض ندارد و مدیر بخش‌های مجاز را انتخاب می‌کند. منو و API هر دو permission را کنترل می‌کنند؛ wildcard مدیر (`*`) حفظ شده است. داده پروژه‌ای نیز همچنان از `employee_project_assignments` scope می‌گیرد.

## پرسنل مراجعه روزانه

رابط `studio_daily_visit_personnel` نام پرسنل، عنوان کار و دستمزد را snapshot می‌کند. برای هر دستمزد یک `personnel_salary_records` و یک هزینه canonical در `expenses` با لینک `atelier_expense_sources` ایجاد می‌شود؛ ledger دوم وجود ندارد. هزینه پرسنل و سود اولیه در سرور محاسبه می‌شوند.

تغییر مبلغ پیش از پرداخت، همان تعهد را اصلاح می‌کند. حذف تخصیص بدون پرداخت، هزینه را reverse و رکورد حقوق را void می‌کند و تاریخچه رابطه را با وضعیت `removed` نگه می‌دارد. اگر پرداختی انجام شده باشد، ویرایش یا حذف مستقیم رد می‌شود و باید فرآیند اصلاح مالی انجام شود.

## Migration

`009_atelier_packages_personnel` فقط تغییرات additive و idempotent دارد: ترتیب کاتالوگ، حقوق ثابت، permission مستقیم، عناوین مراجعه و تخصیص پرسنل مراجعه. هیچ جدول یا داده تاریخی حذف نمی‌شود.
